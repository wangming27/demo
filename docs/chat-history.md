# 对话历史与资源存储

每次用户提问对应一条 `chat_histories`，每次模型调用对应一条 `chat_replies`，每次工具调用对应一条 `chat_tool_calls`。主表只存 `model_id`，通过模型配置表查模型信息，不复制模型名称、API 地址或密钥。删除模型配置采用软删除，历史关联保留；模型配置后续修改会影响关联查询显示的信息。

主表包含用户、会话、请求 ID、前一条记录和重试来源、提问、状态、上下文用量和容量、资源描述、阶段耗时及错误。回复和工具记录通过外键关联，使用同一主记录分配的 `sequence` 排序。回复保存每轮正文、模型思考正文（`reasoning_content`，API 字段为 `reasoningContent`）、实际 `finish_reason`、是否最终回复及该轮 token 用量；未返回思考内容时字段为 `null`，调试原始报文不写入历史表。思考阶段另保存时间区间。缺失的模型用量和容量为 `null`，占比在读取时由最后一轮输入 token 数除以容量计算，不猜测容量，也不累加不同轮的上下文用量。

`requestId`、`conversationId`、`previousHistoryId`、`retryOfHistoryId` 是可选的 UUID。网页为每次提交生成请求 ID，为页面内会话生成会话 ID，并关联上一次成功回复。同一用户的请求 ID 唯一；内容相同且已成功的请求重放已保存的正文、来源和用量，不再次调用模型。正在执行、失败或内容冲突的重复请求返回 409；重试使用新的请求 ID，并可传 `retryOfHistoryId`。重放不包含思考正文或调试数据。前序和重试记录必须属于当前用户和同一会话，前序记录必须已成功。

模型/工具调用前创建运行记录；流式正文和思考正文约每秒写入一次，完成或出错时再次保存。取消不取消数据库收尾写入。服务每分钟巡检，超过五分钟没有心跳的运行记录及其运行中的子记录标记为 `INTERRUPTED`；进程突然终止时，最多损失最后一次检查点之后的正文和思考内容。数据库故障会停止上游生成，恢复后未能收尾的记录由巡检处理。

## 资源文件

配置 `CHAT_STORAGE_ROOT` 为服务可写的私有目录，默认是 API 工作目录下的 `.chat-storage`。生产环境使用持久卷上的绝对路径。文件位于：

```text
<CHAT_STORAGE_ROOT>/<userId>/<historyId>/<resourceUUID>.<extension>
```

数据库 `resources` 仅存 ID、名称、MIME、字节数、SHA-256、存储后端、内部 key 和创建时间。目录和文件分别以 0700 和 0600 创建，文件先写临时文件再原子重命名。下载前校验大小及哈希，不接受客户端文件路径，也不挂载公开静态目录。API 响应不暴露内部 key。

当前保存本次最后一条用户消息新附带的 PNG、JPEG、WebP，单张最多 2 MB、最多四张，整个请求图片最多 8 MB。之前消息的图片由其原始提问记录保存，不重复复制。前端仍按现有协议向模型发送历史图片；数据库不保存 base64。工具输出包含完整数据、来源及警告，超过 128 KiB 时保存为 JSON 文件，工具表存资源 ID 引用，不截断原始输出；单份资源上限为 8 MiB。

删除历史时先标记软删除，再删除其私有目录；文件删除失败会在巡检时重试。失去数据库引用的资源文件和临时文件保留至少 24 小时后清理，运行中的记录不会被资源清理处理。用户物理删除后，数据库级联删除其历史记录，遗留文件同样由孤儿清理回收。第一版使用本地私有文件存储，不跨提问去重；迁移对象存储时可沿用资源描述和鉴权入口。

数据库和资源目录应作为同一备份集备份、恢复。备份时暂停新生成及清理任务，完成数据库快照和资源复制后恢复服务；只备份数据库无法恢复资源正文。部署新版本先执行 `pnpm db:deploy`，再启动服务。

## 历史 API

接口复用登录会话鉴权、Origin 校验及限流，仅访问当前用户记录。

| 方法   | 路径                                                 | 作用                                                   |
| ------ | ---------------------------------------------------- | ------------------------------------------------------ |
| GET    | `/api/chat/histories?page=1&pageSize=20`             | 分页列表，pageSize 上限 100                            |
| GET    | `/api/chat/histories/feed?cursor=<上一页nextCursor>` | 聊天页历史，每次最多 10 条提问，含回复、来源和图片描述 |
| GET    | `/api/chat/histories/:id`                            | 主记录、逐轮回复、工具调用及排序后的 ID 链             |
| GET    | `/api/chat/histories/:id/resources/:resourceId`      | 鉴权下载资源                                           |
| DELETE | `/api/chat/histories/:id`                            | 软删除历史并回收资源，运行中的记录返回 409             |

成功的普通/流式回答增加 `historyId`。历史详情独立返回 `replyChain`、`toolCallChain`，不在主表重复保存 ID 数组。各表保存开始/结束时间和总耗时，流式主表另保存首响应、思考及工具阶段时间区间。

聊天页的 `feed` 接口在 `reply.reasoningContent` 返回该轮保存的思考正文，没有思考内容时为 `null`；前端恢复历史回复后在「模型思考」区域按 Markdown 渲染。

聊天页首次获取最近 10 条提问，向上滚动加载更早记录，保留当前可见消息的位置。`feed` 按创建时间、ID 倒序返回，页面按正序显示；`nextCursor=null` 表示没有更早记录。游标属于当前用户，插入新消息不会使旧页重复。刷新后继续最近的会话，其他会话及失败记录只展示，不混入模型上下文；向上翻页不会突破模型请求的消息数、文本和图片大小上限。历史图片通过资源接口展示，仅在继续提问需要它们时读取为模型输入。

「会话配置」侧栏支持设置携带历史轮数（0–24），默认 0，即每次仅发送当前问题。每轮为一条用户提问和一条成功的最终回复；选择大于 0 时，从当前会话最近的完整历史向前选取，按时间顺序发送，并继续遵守 50 条消息、60,000 字符和请求图片大小上限。当前问题不计入历史轮数，失败及中断的记录不计入；查看历史的分页数量不受该配置影响。

配置按用户 ID 保存在当前浏览器的 `localStorage` 中，保存后从下一次发送生效，不影响正在生成的回答；刷新或重新登录同一账号会恢复设置。不同浏览器分别配置，存储缺失或无效时使用默认值。浏览器拒绝保存时，设置仍在当前页面生效，并在面板中显示提示。
